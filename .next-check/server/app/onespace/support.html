THE STARTING POINT

When people work around the ERP, there is something to learn.

A spreadsheet outside the system may point to an unclear report, an awkward workflow, missing training, or a genuine product gap. We investigate the cause before recommending another custom feature or a larger server.

01

Understand the system you have

For an existing installation, we review the version, installed applications, customisations, integrations, data concerns, and hosting responsibilities. The output is a prioritised improvement plan.

  • Existing-system and customisation review
  • Issue classification by impact and urgency
  • A practical sequence of fixes and improvements
02

Make support expectations explicit

The agreement defines how requests are raised, which hours are covered, how incidents are prioritised, and when escalation happens. Response targets and resolution expectations are discussed separately.

  • Support channels and coverage
  • Incident priorities and escalation contacts
  • Included work and separately quoted changes
03

Change with evidence

Updates and new features should be tested against the workflows the team depends on. We plan backups, a test environment where appropriate, release checks, and a rollback route before production changes.

  • Compatibility checks and regression testing
  • Backup and recovery responsibilities
  • Training refreshers and a reviewed improvement backlog

WHAT THIS MAKES POSSIBLE

Better work, in practical terms.

  1. A clear place to raise and prioritise issues.
  2. Changes evaluated against the work they affect.
  3. An ERP that can evolve with the people using it.

BEFORE WE BEGIN

Good questions. Clear answers.

Can you support a system implemented by someone else?+

We can assess an existing installation for takeover. Access, source availability, version compatibility, custom work, and unresolved issues determine the transition plan and scope.

Are upgrades and new features included?+

Included maintenance, version upgrades, functional support, and development are listed in the agreement. A new feature request is assessed against that scope before work begins.

Can hosting be included?+

Yes, hosting can be discussed with NestCloud. The proposal should make application support, infrastructure operations, backups, and incident ownership clear.
